# Final checklist

Do this check before you give the text to the user. If a line fails, correct
the text and do the check again. Rule numbers are ASD-STE100 Issue 9 numbers.

This file summarizes the rules in `rules.md`. The official standard is the
authority (see `rules.md`).

## Words (Section 1)

- [ ] Rule 1.1: each word is approved in the dictionary, a technical noun, or
      a technical verb. Each word you are not sure of was looked up in
      `word-choices.md`. A word that is not there is reported as needing a
      check in the Issue 9 dictionary, not as approved or not approved.
- [ ] Rule 1.2: each approved word is used only as its approved part of speech
      ("do a test", not "test the pump"; "do a check of", not "check").
- [ ] Rule 1.3: each approved word has its approved meaning.
- [ ] Rule 1.4: each verb and adjective is in an approved form.
- [ ] No word that `word-choices.md` lists is in the text, in the part of
      speech that it gives. A word in a technical noun (Rule 1.6) or in
      quoted text, such as a placard (Rule 1.5, category 10), stays as the
      source writes it.
- [ ] Rule 1.7: no technical noun is used as a verb.
- [ ] Rule 1.11: each item has one technical noun in all of the text.
- [ ] Rule 1.13: no technical verb is used as a noun.
- [ ] Rule 1.14: spelling is American English, except in quoted text.

## Multi-word nouns (Section 2)

- [ ] Rule 2.1: no multi-word noun has more than three words. A hyphenated
      group counts as one word.
- [ ] Rule 2.2: a technical noun of more than three words is written in full
      the first time, then in a shorter form or with hyphens.
- [ ] A long noun whose meaning the source does not show is kept, with
      `[needs: meaning of "<noun>"]`.

## Verbs (Section 3)

- [ ] Rules 3.2 and 3.4: each verb is the infinitive, the imperative, the
      simple present, past, or future, or a past participle as an adjective.
      No "has/had" perfect, no progressive, no modal passive ("must be
      removed", "can be adjusted").
- [ ] Rule 3.5: each "-ing" word is a technical noun, a modifier in a
      technical noun, or an approved "-ing" word.
- [ ] Rule 3.6: each sentence is in the active voice. A passive appears only
      in descriptive text, and only if the agent is unknown. No agent was
      invented. A specific agent the source implies but does not name is
      `[needs: actor]`.
- [ ] Rule 3.7: an action is described with an approved verb where one
      exists.
- [ ] "Shall", "should", "may", and "have to" are not used (dictionary: MUST,
      CAN, or an imperative).

## Sentences (Section 4)

- [ ] Rule 4.1: each sentence is short, clear, and accurate. Each descriptive
      sentence has one topic.
- [ ] Rule 4.2: no noun, verb, subject, or article was omitted. No
      contractions.
- [ ] Rule 4.3: each vertical list has a colon before the first item, an
      uppercase letter at the start of each item, a period only after a full
      sentence and after the last item, and no comma or semicolon after an
      item.
- [ ] Rule 4.5: articles or "this"/"these" are used where applicable.

## Procedures (Section 5)

- [ ] Rule 5.1: each procedural sentence, including each safety instruction,
      has 20 words or less (count with Section 8).
- [ ] Rule 5.2: each sentence has one instruction, unless the actions occur
      at the same time.
- [ ] Rule 5.3: each instruction is in the imperative. No "you should",
      "you must", or "you have to" before its verb, unless "must" is very
      important for safety or gives an important condition (p.89-90).
- [ ] Rule 5.4: a condition the reader must know first comes first, with a
      comma before the command. An "until" end point after the command is not
      such a condition ("Continue until ...", p.88). A "before" or "after"
      clause that only gives the sequence of two actions is not such a
      condition either: it can stay after the command (`rules.md`, Rule 5.4).
- [ ] Rule 5.5: no note gives an instruction, a requirement, or a limit, or
      uses the imperative. Each note sentence has 25 words or less.

## Descriptions (Section 6)

- [ ] Rule 6.3: each descriptive sentence has 25 words or less. A description
      or a note in a procedure is descriptive (p.95).
- [ ] Rule 6.4: each paragraph starts with a topic sentence.
- [ ] Rule 6.5: each paragraph has one topic.
- [ ] Rule 6.6: each paragraph has six sentences or less.
- [ ] No imperative in descriptive text.

## Safety instructions (Section 7)

- [ ] Rule 7.1: each risk of injury or death is a warning. Each risk of
      damage only is a caution.
- [ ] Rule 7.2: each safety instruction starts with a command or a condition.
- [ ] Rule 7.3: each safety instruction gives the risk or possible result,
      if the source gives it.
- [ ] Each command, condition, and risk comes from the source. A missing part
      is `[needs: command]`, `[needs: condition]`, `[needs: risk or result]`,
      or `[needs: level of risk]`, only where `SKILL.md` Section 7 says so.
- [ ] Each command agrees with the work steps it applies to.
- [ ] No safety data was removed.

## Punctuation and word count (Section 8)

- [ ] Rule 8.1: there is no semicolon.
- [ ] Rule 8.2: words that are directly related are hyphenated (for example,
      a two-word adjective before a noun).
- [ ] Rule 8.3: parentheses are used for the uses that Rule 8.3 lists
      (references, item identifiers, step numbers, abbreviations, singular
      and plural, explanations, alternatives). The rule permits these uses.
      It does not forbid other uses, so do not report one as a Rule 8.3
      finding.
- [ ] Rules 8.4 to 8.7 were used to count words.

## Writing practices (Section 9)

- [ ] Rule 9.1: a replacement word did not change the meaning. Where it
      would, the sentence has a different construction.
- [ ] Rule 9.2: ABOVE and BELOW are only for physical positions (limits use
      MORE THAN and LESS THAN).
- [ ] Rule 9.3: there are no phrasal verbs, except approved ones (PUT ON,
      COME ON).
- [ ] Rule 9.4: the same type of work step has the same wording each time.

## Accuracy (Rules 4.1, 9.1)

- [ ] Each technical noun is the same as in the source text.
- [ ] Each number, tolerance, and unit is the same as in the source text.
- [ ] No step was removed, added, or put in a different sequence.
- [ ] No fact, value, name, tool, or actor was added that is not in the source.
      Each gap is a `[needs: …]` and is listed under **Gaps**.
